# 机器人地图编辑平台

当前阶段聚焦可行走区域编辑与通过性验证，定位和导航保留后续扩展。

## 功能

- 导入人工灰度栅格地图（深色像素表示障碍），原图以 BLOB 单独保存，修订不覆盖原图。
- 在真实米制坐标中绘制禁行区、调整地图原点；前端显示比例只影响 SVG 像素，不参与计算。
- 输入机器人完整宽、长尺寸，后端按水平和竖直两种矩形整机外廓做保守膨胀。
- 使用积分图生成可行中心配置空间，再进行 BFS；不是只检查机器人中心点。
- 修订支持前端撤回/重做、服务端保存和命名版本恢复。
- 验证结果带算法版本；工程、栅格和状态持久化在 SQLite，重开同一 URL 后复核结果一致。

## 启动

```bash
cd backend
python -m pip install -r requirements.txt
./run.sh
```

```bash
cd frontend
npm install
npm run dev
```

打开 Vite 输出的地址，点击“使用宽窄门示例”可直接验证。示例包含宽门、窄门和贴边障碍，窄门场景下即使中心线为空，较大机器人也应判定不可通过。

## 测试

```bash
cd backend && python -m pytest
cd frontend && npm run build
```


## 定时检查点与临时封路

- 检查点位置容差、姿态容差均可留空：保存与核对共用同一缺省含义（位置容差为 1.5 个栅格、姿态容差为半个角层），不再出现“能保存、核对却返回服务器错误”。
- 限时封闭区按半开区间判定：封闭开始时刻必须已经在撤离（恰在该时刻结束的撤离动作允许），封闭结束时刻起才允许进入。
- 判断使用长方形整机外廓：直行覆盖两端位姿、原地转向覆盖整段角扫掠；禁止停留的通道不能充当等待区，机器人只能停在显式安全等待区或在安全位置转向耗时。
- 给出可行结论时同时返回逐段过程（就位、到达、转向、等待、通过检查点）与独立重放结果；重开保存方案后用保存时的地图与状态再算一遍，结论必须一致。
- 勾选“先保留原几何路线重排时间”后，先在冻结的原路线上重排并返回其封路与窗口依据，无法安排时再全局重新选路；无法安排、姿态不符、预算内未证明分别用 timed_blocked/window_missed、orientation_mismatch、search_incomplete 表达。

## 联合出发时刻规划

- 多条任务共享工程的限时封闭区与检查点窗口；每条任务只覆盖起点/终点/姿态/速度/机体尺寸，系统只调整出发时刻，不改变路线几何。
- 已承诺（committed）任务出发时刻固定、不可移动，仅作为约束参与核对；可调任务在 [最早, 最晚] 范围内按时间量子离散搜索。
- 冲突按栅格-时间占用判定：逐段时序还原成占用区间并按整机外接圆保守膨胀，同一栅格被两项任务在同一半开区间占用即冲突。
- 同时比较两种目标：总等待最少（min_total_wait）与最晚完成时间最小（min_makespan），各自给出候选。
- 单条路线可行不代表联合可行；搜索预算耗尽（search_incomplete，候选标记为部分结果）与证实无解（infeasible，附单任务失败/冲突组合计数与样例）分别表达。
- 候选只是建议：保存与采用都不修改原任务与工程状态；采用前用当前地图与承诺重算同一出发安排，地图/封闭区变化使依赖该地图的候选失效，承诺变化只使记录了该承诺任务的候选失效。
