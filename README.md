# 机器人地图编辑平台

当前阶段聚焦可行走区域编辑与通过性验证，定位和导航保留后续扩展。

## 功能

- 导入人工灰度栅格地图（深色像素表示障碍），原图以 BLOB 单独保存，修订不覆盖原图。
- 在真实米制坐标中绘制禁行区、调整地图原点；前端显示比例只影响 SVG 像素，不参与计算。
- 输入机器人完整宽、长尺寸，后端按水平和竖直两种矩形整机外廓做保守膨胀。
- 使用积分图生成可行中心配置空间，再进行 BFS；不是只检查机器人中心点。
- 修订支持前端撤回/重做、服务端保存和命名版本恢复。
- 验证结果带算法版本；工程、栅格和状态持久化在 SQLite，重开同一 URL 后复核结果一致。

## 定时检查点与临时封路

 - 检查点的 `tolerance` / `orientation_tolerance` 可省略，缺省与显式空值走同一套默认含义，保存与核对结果一致。
 - 可行结论附带逐段时间线（到达、转向、等待、通过检查点），可逐段重放，而不是只给最终结论。
 - 临时封路区只在 `[close_start, close_end)` 内禁止进入：到达恰好等于封闭开始算已撤离，恰好等于开放时刻允许进入。
 - 机器人可以在声明的等待区内等候开放或改走其他路线；封闭期间身体的任何部分（含转向扫掠）都不得留在区域内，未声明为等待区的通道不能充当等待区。
 - 修改封闭时段或检查点窗口后，可以保留原几何路线只重排时间（`keep_geometry`），再与重新选路比较；无法安排、姿态不符、搜索尚未完成分别用 `unschedulable`、`pose_mismatch`、`search_incomplete` 说明。
 - 保存的方案保留自己的地图版本与封路依据，重开后逐段复核结论一致。

## 启动

```bash
cd backend
python -m pip install -r requirements.txt
./run.sh
```

```bash
cd frontend
npm install
npm run dev
```

打开 Vite 输出的地址，点击“使用宽窄门示例”可直接验证。示例包含宽门、窄门和贴边障碍，窄门场景下即使中心线为空，较大机器人也应判定不可通过。

## 测试

```bash
cd backend && python -m pytest
cd frontend && npm run build
```
